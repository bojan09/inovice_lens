# Phase 4: genuine PDF, Word, Excel and Sheets-compatible exports

Scope: export the CORRECTED document, on device, in four formats, with a real preview, progress, cancel, error handling and a download lifecycle. Every output is re-opened with an independent reader and compared with the corrected values. English only. Batch (queue) and saved projects are Phase 5.

## Run

```bash
npm test                 # includes tests/unit/export.test.js (external tools used when installed)
npm run test:browser     # includes tests/browser/export.e2e.js (real downloads, re-read with poppler/python-docx/openpyxl/LibreOffice)
```

Open **Export** in the editor (current file preselected) or on Convert (all recognized files; several files become one ZIP).

## What it exports

| Format | Modes | Content |
|---|---|---|
| PDF | **Original appearance**: the page images in the editor's page order and rotation, optional invisible text layer (words as recognized, NOT your edits). **Structured**: reconstructed document (details, line-item table, page text, review notes). | pdf-lib 1.17.1; pages selectable; real `pdftotext`/`pdfinfo`/`pdfimages` checks |
| Word (.docx) | Structured only | docx 9.13.0: title, details table, line-item table (right-aligned numbers), page text, review notes, footer |
| Excel (.xlsx) | Structured only | write-excel-file 4.1.1: sheets Summary, Line items / Table, Page text, Review notes. Amounts and quantities are **numeric cells** with number formats; ISO dates are **date cells**; Unicode intact |
| Google Sheets | CSV (UTF-8 + BOM, CRLF, RFC 4180) or "Copy for pasting" (tab-separated) | One table per CSV (line items, summary, table, text, notes). No OAuth, no Drive/Sheets API. Open via Sheets "File > Import" or paste |

Unsupported pairs are disabled **with the reason shown** (e.g. Word/Excel cannot reproduce a scanned page: use PDF "Original appearance").

## Design decisions (and why)

- **One neutral export model** (`js/export/data.js`) feeds every exporter, so formats cannot disagree. Money is parsed to integer minor units via `js/money.js`; unreadable or ambiguous amounts stay text (never guessed); nothing is recomputed.
- **Human formats show what the user typed** ("EUR 245.00"); **machine formats get exact numbers**: CSV uses exact decimal text built from minor units (no float), XLSX uses the nearest double with a 2-decimal format (a spreadsheet cell must be a double; it displays the exact amount).
- **Open problems travel with the file**: "Include review notes" (default on) appends the checks still failing at export time, so a file with an unresolved total mismatch says so.
- **Preview == download**: the dialog generates once; the PDF preview is the generated bytes rendered by pdf.js; the Word preview shows the content the file is built from (Word layout cannot be rendered in a browser); Excel/CSV preview shows the cells written.
- **Safety**: file names are sanitised (no separators, accents folded, <= 80 chars, ZIP names de-duplicated); text cells that start with `= + - @` get a leading apostrophe in CSV/TSV; the CSP is unchanged (the UMD Excel writer is a same-origin classic script, the rest are ES modules); only same-origin GETs (verified).
- **Cancellation** is honest: it stops between pages / steps and a cancelled run never completes later (verified). A single library call (the final PDF save, the DOCX/XLSX pack) cannot be interrupted, so cancel during those takes effect when the call returns.

## Known limitations

- **Not pixel-faithful conversions.** Word/Excel are reconstructions of the corrected values; arbitrary layout is not reproduced. PDF "Original appearance" is the faithful mode.
- **PDF structured uses the standard Helvetica/Courier fonts (WinAnsi).** Cyrillic/CJK etc. become `?` and the count is reported in the dialog; Word, Excel and CSV keep full Unicode. (Embedding a TTF would need `@pdf-lib/fontkit`; not done.)
- The PDF "Original appearance" text layer is the **recognized** text (no edits), positioned by word boxes (no per-glyph width fitting), so selecting text may not align exactly; it is for search/copy.
- The original-PDF page size is exact for text PDFs and "fit inside A4" for images/scans (the real DPI is unknown). Page images are JPEG (quality 0.88, up to 3 MP per page): no lossless/PDF-A output, no PDF/A claims.
- A DOCX/XLSX/CSV cannot be rendered to a pixel preview in the browser; the preview is the content, labelled as such.
- Browser behaviour verified in Chromium only (download, clipboard, `<dialog>`); LibreOffice/openpyxl/python-docx are the independent readers. **Microsoft Word, Excel and Google Sheets themselves were not available** to open the files.
- The Word file is 1.3 MB of vendored JS loaded only when first used (docx is unminified upstream).
- No in-dialog password/encryption, no digital signature, no per-file option sets in the multi-file ZIP (the same options apply to every file; page selection applies to a single file).
- Extraction accuracy is unchanged: measured only on a synthetic corpus (see PHASE3.md). Exports state the recognized, corrected values, not verified truth.

## Handoff to Phase 5

- `exportOne` / `zipResults` (`js/export/index.js`) are pure of the DOM except `renderPage`; Phase 5 batch export can call them per queue item. The dialog already takes several files.
- Project persistence should store `toPlain(doc)` plus the original `File` blob; exports re-derive everything from them.
- "Combined PDF" and "consolidated XLSX across files" (Phase 5) are NOT implemented: multi-file export is one ZIP with one file per document.
